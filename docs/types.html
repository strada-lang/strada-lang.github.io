Types & Variables

Understanding Strada's type system and variable declarations.

Type System Overview

Strada is typed. Every variable has a type, either declared explicitly or inferred from its sigil ($ → scalar, @ → array, % → hash).

Type Description Example
int64-bit signed integer (tagged pointer, zero heap allocation)42, -17
num64-bit floating point3.14, -0.5
strUTF-8 string"hello"
arrayDynamic array(1, 2, 3)
hashKey-value map("a" => 1)
scalarGeneric type (any value)Any value
voidNo value (function returns)-
undefUndefined valueundef
dynamicContext-sensitive return typeFunction returns

Dynamic Return Type

The dynamic return type allows functions to return different types based on calling context, similar to Perl's wantarray():

func flexible() dynamic {
    if (core::wantarray()) {
        my array @r = (1, 2, 3);
        return @r;
    }
    return 42;
}

my array @arr = flexible();  # (1, 2, 3)
my int $val = flexible();    # 42

Context functions: core::wantarray(), core::wantscalar(), core::wanthash(). core::wantarray() also works in a function without a dynamic return type:

func ctx() {
    return core::wantarray() ? "list" : "scalar";
}
my @l = (ctx());   # $l[0] is "list"
my $s = ctx();     # "scalar"

Sigils

Like Perl, Strada uses sigils to identify variable types:

$ - Scalar

Single values: integers, floats, strings, references, objects

@ - Array

Ordered lists of values

% - Hash

Key-value maps (associative arrays)

Variable Declaration

Variables are declared with my followed by type and sigil:

# Scalar variables ($ sigil)
my int $count = 0;
my num $price = 19.99;
my str $name = "Alice";
my scalar $anything = 42;

# Array variables (@ sigil)
my array @numbers = (1, 2, 3);
my array @empty = ();

# Hash variables (% sigil)
my hash %config = (
    "host" => "localhost",
    "port" => 8080
);
Optional type annotations Type annotations are optional. When omitted, the sigil determines the default type: $ defaults to scalar, @ to array, and % to hash. 
# These pairs are equivalent:
my $foo = 42;           # same as: my scalar $foo = 42;
my @items = (1, 2);    # same as: my array @items = (1, 2);
my %lookup = ();        # same as: my hash %lookup = ();
our $bar = "hello";    # same as: our scalar $bar = "hello";
Use explicit types like int, str, or num when you want tighter compile-time checking.
Declaration without initialization Variables can be declared without an initial value. A typed scalar starts as its type's empty value; an untyped scalar starts as undef. 
my int $x;     # 0
my num $f;     # 0
my str $s;     # ""
my $u;         # undef (same for "my scalar $u;")
my @list;      # empty array
my %map;       # empty hash
$x = 10;        # Now $x is 10
An int variable always holds an integer: assigning a value that is not statically an integer converts it, so my int $n = "12abc"; stores 12.
Same name, different sigils $t, @t and %t are three separate variables, as in Perl: my %t; my @t; my $t; in one scope declares all three.

Constants

Use const to declare compile-time constants:

# Global constants (compile to C #define)
const int MAX_SIZE = 100;
const str VERSION = "1.0.0";
const num PI = 3.14159;

# Sigil is optional for const
const int LIMIT = 50;        # Without sigil
const int $RETRIES = 3;    # With sigil: read it as RETRIES or $RETRIES

# Local constants
func example() void {
    const int LOCAL_MAX = MAX_SIZE / 2;
    # ...
}
Zero overhead for global constants Global constants with literal values compile to C #define macros, so there's no runtime overhead.

Package-Scoped Variables (our)

Use our to declare package-scoped global variables backed by the runtime global registry. Unlike my globals, our variables are accessible across dynamically loaded modules.

# Declare our variables at file level
our int $count = 0;
our str $name = "hello";
our int $no_init;          # 0, like "my int $x;" (num: 0, str: "")

# In another package
package Config;
our str $host = "localhost";  # Registry key: "Config::host"
our int $port = 8080;

package main;

func modify() void {
    $count = 42;              # Writes to global registry
    $count += 5;              # Compound assignment works
    $name .= " world";       # String append works
}

func main() int {
    say($count);              # 0
    modify();
    say($count);              # 47
    return 0;
}
our vs my at package level my globals compile to C global variables — fast but not visible across import_lib boundaries. our globals use the runtime registry — slightly slower but accessible from any module via core::global_get("pkg::name").

Integers (int)

Integers use tagged pointer representation: they are encoded directly in the pointer with zero heap allocation. This makes integer arithmetic, comparisons, loop counters, and array indexing extremely fast with no memory management overhead.

my int $a = 42;
my int $b = -17;
my int $hex = 0xFF;      # Hexadecimal: 255
my int $oct = 0o755;     # Octal: 493
my int $bin = 0b1010;    # Binary: 10

# Arithmetic
my int $sum = $a + $b;
my int $mod = $a % 5;     # Modulo: 2
my int $pow = 2 ** 10;   # Power: 1024

Floating Point (num)

my num $pi = 3.14159;
my num $sci = 1.5e10;    # Scientific notation
my num $neg = -0.001;

# Math operations
my num $sqrt = math::sqrt(16);     # 4
my num $sin = math::sin($pi);     # ~0
my num $floor = math::floor(3.7); # 3

Strings (str)

my str $s1 = "Hello";
my str $s2 = 'Single quotes also work';

# Escape sequences (in double quotes)
my str $newline = "Line 1\nLine 2";
my str $tab = "Col1\tCol2";
my str $quote = "She said \"Hi\"";

# Concatenation
my str $full = $s1 . " World";

# Repetition
my str $repeated = "ab" x 3;  # "ababab"

# String functions
my int $len = length($s1);           # 5
my str $upper = uc($s1);            # "HELLO"
my str $lower = lc($s1);            # "hello"
my str $sub = substr($s1, 0, 3);    # "Hel"
my int $pos = index($s1, "ll");    # 2

Arrays (array)

# Declaration
my array @nums = (1, 2, 3, 4, 5);
my array @mixed = (1, "two", 3.0);
my array @nested = ([1, 2], [3, 4]);

# Pre-allocate capacity for performance
my array @big[1000];  # Empty array with capacity for 1000 elements

# Access elements (use $ sigil for single element)
my int $first = $nums[0];      # 1
my int $last = $nums[-1];     # 5 (negative index)
my int $top = $#nums;           # 4 (last index; $#{$ref} or $#$ref for a reference)

# Modify elements
$nums[0] = 10;

# Array functions
push(@nums, 6);                 # Add to end
my scalar $popped = pop(@nums);  # Remove from end
unshift(@nums, 0);              # Add to beginning
my scalar $shifted = shift(@nums); # Remove from beginning

my int $length = size(@nums);   # Get length
my int $count = @nums;         # Scalar context: array count
my str $joined = join(",", @nums); # Join to string
my array @sorted = sort(@nums);  # Sort array
my array @rev = reverse(@nums);  # reversed copy (original unchanged)
my str $back = reverse("abc");  # "cba": in scalar context reverse joins and reverses the string

# Destructuring - unpack array into variables
my ($a, $b, $c) = @nums;           # Basic destructuring
my (int $x, str $y) = @mixed;    # With explicit types
my ($p1, $p2) = get_pair();      # From function return

# List flattening (Perl-style) - array VALUES expand in list context
my array @middle = (3, 4);
my array @all = (1, 2, @middle, 5);   # (1, 2, 3, 4, 5)  array variable
my array @lit = (1, (2, 3), 4);      # (1, 2, 3, 4)     parenthesized list
my array @sp  = ("a", split(",", "b,c")); # ("a","b","c")    array-returns / builtins

# References are scalars - they do NOT flatten (nest one array via a ref)
my array @withref = (1, [2, 3], 4);    # 3 elements: 1, an arrayref, 4

# Scalar context - assign array to scalar to get count
my int $n = @all;  # 5
What flattens In list context, anything that is an array value splices its elements in: @array variables, parenthesized lists (…), map/grep/sort, calls declared to return array, and array builtins (split, keys, values, …). References ([…], \@a) are scalars and stay one element, exactly as in Perl. To spread an array as separate function arguments, use ...@array.
Array Access Sigil When accessing a single element, use $array[index], not @array[index]. The @ sigil is for the whole array.

Hashes (hash)

# Declaration
my hash %person = (
    "name" => "Alice",
    "age" => 30,
    "city" => "NYC"
);

# Pre-allocate capacity for performance
my hash %cache[500];  # Empty hash with capacity for ~500 entries

# Access values (use $ sigil for single value)
my str $name = $person{"name"};    # "Alice"

# Add/modify values
$person{"email"} = "alice@example.com";
$person{"age"} = 31;

# Hash functions
my array @keys = keys(%person);        # Get all keys
my array @vals = values(%person);      # Get all values

# Check if key exists
if (exists(%person, "email")) {
    say("Has email");
}

# Delete a key
delete(%person, "city");
delete $person{"email"};           # Perl form, no parentheses

# keys/values/split in scalar context give a count
my int $nkeys = keys(%person);      # 2
my scalar $klist = [keys(%person)]; # keep the list: an array reference

# Iterate over pairs
while (my ($k, $v) = each %person) {
    say($k . " = " . $v);
}

# Parenthesized groups of pairs join the hash
my hash %opts = (("a", 1), ("b", 2));  # a => 1, b => 2
Hash Access Syntax Use $hash{key} for element access, NOT %hash{key}. Using %hash{key} is a syntax error.

References

References are created with the backslash operator \:

# References to variables
my int $x = 42;
my scalar $ref = \$x;     # Reference to scalar

my array @arr = (1, 2, 3);
my scalar $aref = \@arr;   # Reference to array

my hash %h = ("a" => 1);
my scalar $href = \%h;    # Reference to hash

# Dereference with arrow
say($aref->[0]);      # 1
say($href->{"a"});    # 1

# Anonymous references
my scalar $anon_arr = [1, 2, 3];    # Array reference
my scalar $anon_hash = {"x" => 1};  # Hash reference

# Assigning through an undef scalar creates the container (autovivification)
my $u;
$u->{"k"} = 1;       # $u is now a hash reference
my $list;
$list->[2] = "z";    # $list is now an array reference with 3 elements
$u->{"a"}{"b"} = 2;  # intermediate levels are created too

Type Conversion

# String to int
my int $n = int("42");

# Int to string (automatic via concatenation)
my str $s = "" . 42;

# Assigning to a typed variable converts
my str $str = 42;       # "42"
my int $i = "12abc";    # 12

That is the default. In a file with use strict "types"; the last two lines are compile errors; see Checked Types below.

Checked Types

By default an annotation converts: my int $n = "12abc"; quietly makes $n the integer 12. A file that starts with use strict "types"; gets compile errors for type mismatches instead, from that line to the end of the file.

use strict "types";

func total(array<int> @prices, num $tax) num {
    my int $sum = 0;
    foreach my int $p (@prices) { $sum += $p; }
    return $sum * (1 + $tax);
}

func main() int {
    my array<int> @list = (10, 20, 30);
    my hash<str, int> %age = ();          # hash<int> means the same
    my str $in = "0.5";

    push(@list, "forty");                 # error: storing a str value in '@list' (declared array<int>)
    $age{"bob"} = "old";                  # error
    my int $half = $list[0] / 2;          # error: `/` gives a num; write int($list[0] / 2)
    say(total(@list, $in));               # error: argument 2 to 'total': expected num, got str
    say(total(@list, $in + 0));           # fine: explicit conversion
    return 0;
}

Every error is reported in one run, with file and line (each is followed by the source line, left out here):

app.strada:14: error: storing a str value in '@list' (declared array<int>)
app.strada:15: error: storing a str value in '%age' (declared hash<int>)
app.strada:16: error: initializing '$half' (declared int) with a num value
app.strada:17: error: argument 2 to 'total': expected num, got str
compilation failed: 4 semantic errors

What is checked

  • my and our initializers, and assignments to declared scalars
  • arguments against declared parameter types, and return values against the declared return type
  • values put into a variable, parameter or function result that declares an element type (my, our and file-level variables alike): literal initializer and assignment lists ((1, 2), (a => 1)), $a[i] = v, $h{k} = v, push, unshift, the declared type of a foreach variable, and array arguments. A hash list that contains more than plain scalar expressions ((%base, k => 1), a call) is not checked.
  • the return values of a function declared array<T> or hash<T>, and that function's result where it is stored, pushed, passed or looped over: my array<int> @a = names(); is an error when names() returns array<str>.

Element types

Arrays and hashes can say what they hold: array<T>, hash<T> or hash<str, T>, where T is int, num, str, scalar or a class name. Reading an element ($list[0], $age{"bob"}, shift(@list)) gives a value of that type. They work in my declarations, parameters and return types.

Conversions

FromToHow
intnumimplicit
numintthe cast int($x)
one character, '/'int or strimplicit (its character code, or the text)
textnumber$s + 0 or int($s)

The cast you will write most often is for division. / always gives a num, so integer division is spelled out; int(...) truncates toward zero, exactly as the implicit conversion did. % is integer modulo and needs no cast.

my int $days = int($diff / 86400);     # cast the division
my int $rest = $diff % 86400;          # % is already an int
my num $frac = $diff / 86400;          # or keep the fraction
return int($total / $count);           # same in a function that returns int

Gradual, one file at a time

  • scalar, unannotated variables and plain array/hash are never checked, in either direction, so typed and untyped code mix freely.
  • The pragma covers its own file: functions, methods, method modifiers, closures, BEGIN/END blocks and file-level initializers. A strict module does not make its users strict, and a strict program does not check the modules it uses.
  • Without the pragma nothing changes. strada --strict-types reports the same mismatches as warnings.
  • strada-interp file.strada reports the same type errors and does not run the program. It enforces the type checks only. Code given with -e and REPL input are not checked.

Objects and method calls

Where the compiler knows an object's class, it checks method arguments against the method's parameters, gives the call the method's declared return type, and checks constructor arguments against the attribute types.

use strict "types";

package Account;
has ro str $owner (required);
has rw num $balance = 0.0;
func deposit(scalar $self, num $amount) void {
    $self->set_balance($self->balance() + $amount);
}

package main;
func main() int {
    my scalar $acct = Account::new(owner => "Ann");
    $acct->deposit("fifty");                  # error: argument 1 to 'Account::deposit': expected num, got str
    my int $who = $acct->owner();             # error: initializing '$who' (declared int) with a str value
    my scalar $b = Account::new(owner => 7);  # error: attribute 'owner' of 'Account': expected str, got int
    return 0;
}

The class is known for:

  • $self in a class's own functions;
  • a variable declared my $v = Pkg::new(...) that the function never assigns again;
  • a typed catch variable, catch (Pkg $e);
  • a class name, Pkg->method(...), and SUPER::method(...).

An object that arrives as a parameter, from a function or out of a container has no known class, and calls on it are not checked. Neither is a method with an around modifier, nor a call through $self to a method that a subclass overrides.

Limits. Element types are checked at compile time only: a value that reaches a typed container through untyped code is not converted. Not checked yet: method calls on an object whose class the compiler does not know (see below) and class element types (array<Point> is accepted). Nested element types (array<array<int>>) are a syntax error. Bare use strict; is accepted and does nothing (Strada already requires declared variables); type checking is use strict "types";.

What typing buys in speed

The pragma itself only adds compile-time checks. The speed comes from the types, with or without it:

What you typeWhat the compiler doesMeasured
my int $i, my num $x localsplain C int64_t / double, no allocationa Mandelbrot inner loop runs at the speed of the C version
int parametersno reference counting on entry or exit
has rw num $x, has rw int $n, used in the class's own methodsarithmetic in C numbers, written back into the attribute's slot; the call site remembers where the attribute lives1.92 s → 0.40 s on 20 million method calls
foreach my int $v (@a) with a body that only reads $vthe loop variable is a C integer0.12 s → 0.10 s summing 100 million elements
/ and ** assigned to a numplain C arithmetic, no temporary value0.09 s → 0.02 s on a 2000×2000 Mandelbrot

No speed difference yet: element types (array<int> and hash<str, num> are checked, but storage is unchanged), str, and method calls on an object whose class the compiler cannot see (one taken out of an array, or a scalar parameter).

A complete program that uses all of this is in the repository: examples/checked_types.strada.

The scalar Type

The scalar type can hold any value and is useful for generic programming:

func print_anything(scalar $val) void {
    say($val);
}

print_anything(42);
print_anything("hello");
print_anything([1, 2, 3]);
