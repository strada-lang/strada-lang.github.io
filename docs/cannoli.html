Cannoli Web Framework

Build web applications with Cannoli, the preforking web server and framework for Strada.

📦 Download Cannoli on GitHub

Overview

Cannoli is a preforking web server and application framework written in Strada. It lives in its own repository and provides:

Routing

URL path matching and HTTP method handling

Request Parsing

Query params, form data, JSON bodies, headers, cookies

Response Building

JSON, HTML, redirects, custom headers, cookies

File Uploads

Multipart form-data parsing for file uploads

SSL/TLS

HTTPS support with certificate configuration

Static Files

Built-in static file serving with directory listing

Four Ways to Deploy

Standalone server, behind nginx with FastCGI, or as a plain CGI program under Apache

Compiled or Interpreted Apps

Load a handler library as a compiled .so, or as a .strada file run by the built-in VM

Production Hardening

Timeouts, limits, stuck-worker watchdog, metrics, reload, systemd

Quick Start

func main() int {
    my scalar $app = Cannoli::App::new();

    # Each route registers a handler: func (hash %req) hash
    Cannoli::App::get($app, "/", func (hash %req) hash {
        return Cannoli::Response::json(200, "{\"message\":\"Hello, Cannoli!\"}");
    });

    Cannoli::App::get($app, "/greet", func (hash %req) hash {
        my str $name = Cannoli::Request::get_param(%req, "name");
        if ($name eq "") { $name = "World"; }
        return Cannoli::Response::text(200, "Hello, " . $name . "!");
    });

    return Cannoli::App::run($app);
}

Cannoli registers a handler per route with Cannoli::App::get / post / put / delete_route (paths may be regexes with capture groups). Each handler takes the request hash %req and returns a response built with Cannoli::Response::html / text / json(code, body). See the examples/ directory in the Cannoli repository for request parsing, headers and cookies, file uploads, and templates.

An application is compiled together with Cannoli's framework sources (src/*.strada). From a Cannoli checkout, build_test.sh does the concatenation and the build (it uses strada from your PATH, or $STRADA, and builds unoptimized with -O0 --no-lto unless STRADA_TEST_FLAGS says otherwise):

./build_test.sh /path/to/myapp.strada    # builds /tmp/myapp
/tmp/myapp

Cannoli::App::run listens on port 8080 with 5 workers by default; call Cannoli::App::configure($app, "cannoli.conf") before run to load a configuration file. The program also accepts the server's options on its command line (-p/--port, -h/--host, -w/--workers, --fastcgi, --socket), which override both: /tmp/myapp -p 3000. Visit http://localhost:8080/ to see your app.

Handlers can also live in a library that the stock cannoli server loads, compiled or interpreted: see Handler Libraries.

Handlers, Request & Response

A route handler has the signature func (hash %req) hash: it receives the request hash %req and returns a response hash built with the Cannoli::Response helpers.

Example: a small JSON API

func main() int {
    my scalar $app = Cannoli::App::new();

    Cannoli::App::get($app, "/health", func (hash %req) hash {
        return Cannoli::Response::json(200, "{\"status\":\"ok\"}");
    });

    # Path capture groups arrive in $req{"captures"}
    Cannoli::App::get($app, "/hello/(\\w+)", func (hash %req) hash {
        my scalar $caps = $req{"captures"};
        my str $who = $caps->[0];
        return Cannoli::Response::text(200, "Hello, " . $who . "!");
    });

    Cannoli::App::post($app, "/echo", func (hash %req) hash {
        my str $msg = Cannoli::Request::get_param(%req, "msg");
        my hash %res = Cannoli::Response::text(200, $msg);
        Cannoli::Response::header(%res, "X-Echo", "1");
        return %res;
    });

    return Cannoli::App::run($app);
}

Handler Libraries

Instead of compiling your routes into a program, you can write a handler library and load it into the stock cannoli server. A library exports cannoli_dispatch($c): it receives the Cannoli object for the request, builds the response on it, and returns $c->done(), or "" to leave the request to the next library.

# app.strada
func cannoli_dispatch(scalar $c) str {
    if ($c->path() eq "/hello") {
        $c->render_text("Hello, " . $c->param("name"));
        return $c->done();
    }
    if ($c->is_post() && $c->path() eq "/api/items") {
        $c->status(201);
        $c->render_json({"created" => $c->json_body()});
        return $c->done();
    }
    return "";   # not ours: next library, the router, or 404
}

The same file runs two ways:

./cannoli --library ./app.strada --dev          # interpreted by the built-in VM: no build step
strada --shared app.strada -o app.so
./cannoli --library ./app.so                    # compiled
./cannoli --library "./app.so:key=value"         # options, passed to cannoli_init()
ExportWhen it runs
cannoli_dispatch($c)Every request (required)
cannoli_init($config)Once at startup, with the options after the colon; returning 0 stops the server from starting
cannoli_after_request($c, $ms)After the response is sent
cannoli_worker_exit()When a worker process ends
cannoli_tick()Periodically, in a separate ticker process

Commonly used methods of $c: method(), path(), path_info(), param($name), header($name), body(), json_body(), is_get() / is_post(); status($code), set_header($name, $value), set_cookie(...), render_text(), render_html(), render_json($data), redirect($url, 0); session_get() / session_set(); start_chunked() / write_chunk() / end_chunked() for streaming; and ws_accept() / ws_recv() / ws_send() for WebSockets.

The return value is not a response. A string returned without touching $c is sent as the body only: application/json when it starts with { or [, otherwise text/plain. Older Cannoli versions read STATUS:, REDIRECT: and RESPONSE: prefixes (and a leading < as HTML) from it, which let user input that a handler echoed choose a redirect or headers. Set library_prefixes = true under [app] to keep that behaviour for an old library.

Mount a library under a URL prefix in the configuration file; the library then sees the rest of the path in $c->path_info():

[library]
/app = /srv/app/app.so
/admin = /srv/admin/admin.strada

Interpreted applications

A .strada file is loaded into the Strada bytecode VM linked into Cannoli; the server itself stays compiled. With --dev (or reload=1) the file is reread when it changes, and a version that fails to load is logged while the last good one keeps serving. lib=DIR adds a directory for the script's own use.

Differences from a compiled library
  • Use $c's methods: interpreted code cannot read the object's fields or call Cannoli's own package functions ($c->html_escape() is there for that reason).
  • All scripts share one VM per worker: give each application's helpers their own package.
  • One interpreted handler runs at a time per worker. That is how classic workers run anyway; with --loop-workers, a handler that waits inside the VM (a slow stream, a WebSocket) holds up that worker's other interpreted requests.
  • Speed: a small text route measured about 86% of the compiled library's throughput. Modules with __C__ blocks (such as JSON) are compiled by the VM with gcc the first time they load.

CGI

In CGI mode Cannoli serves exactly one request: it reads the request from the CGI environment and standard input, writes the response to standard output, and exits. Any application, compiled or interpreted, can be dropped into cgi-bin:

#!/bin/sh
# /usr/lib/cgi-bin/app.cgi  (chmod +x)
exec /usr/local/bin/cannoli --cgi --library /srv/app/app.so
ScriptAlias /app /usr/lib/cgi-bin/app.cgi     # Apache, with mod_cgi or mod_cgid
# http://host/app/users/7  ->  the application sees the path /users/7

The application sees the path after the script's URL; $c->script_name() gives the script's own URL for building links. --cgi is implied when the web server sets GATEWAY_INTERFACE. Startup messages and errors go to standard error (the web server's error log), never into the response. CGI cannot do WebSockets or keep anything in memory between requests, and each request pays for a process start (about 15 ms for a small library).

A # after a value starts a comment (port = 8080 # http); cannoli -t -c file.conf checks a configuration without starting. See contrib/ in the repository for a systemd unit and an nginx example.

More Features

Cannoli also includes form/JSON body parsing, file uploads, cookies and sessions, templates, static-file serving with ranges and compression, chunked/streaming responses, HTTPS/TLS, WebSockets, and Perl handlers through an embedded interpreter (lib/perl). See the Cannoli README for all of them. The examples/ directory has programs built on Cannoli::App (hello_app, api_app, upload_demo, headers_demo, static_server, template_demo), a handler library that runs compiled or interpreted (myapp.strada), and a Perl application (perl/).
