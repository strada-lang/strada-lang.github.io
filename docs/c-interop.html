C Interoperability

Embed C code directly in Strada programs and interface with C libraries.

Overview

Strada provides powerful C interoperability through __C__ blocks, which let you embed raw C code directly in your Strada programs. This enables:

Direct C Access

Call any C library function, use C data structures, and leverage existing C code.

High Performance

Write performance-critical code in C while keeping the rest of your program in Strada.

System Integration

Access operating system APIs, hardware interfaces, and low-level functionality.

__C__ Blocks

There are two types of __C__ blocks:

Top-Level Blocks

Place at file scope for includes, global variables, and C helper functions:

__C__ {
    #include <stdio.h>
    #include <math.h>
    #include <openssl/ssl.h>

    // Global state
    static SSL_CTX *g_ssl_ctx = NULL;
    static int g_initialized = 0;

    // C helper function
    static double fast_distance(double x1, double y1,
                                double x2, double y2) {
        double dx = x2 - x1;
        double dy = y2 - y1;
        return sqrt(dx*dx + dy*dy);
    }
}
Top-level blocks appear at the top of the generated C file, before any Strada-generated code. This ensures includes and declarations are available throughout the file.

Statement-Level Blocks

Use inside functions to write inline C code with access to Strada variables:

func calculate_sqrt(num $x) num {
    __C__ {
        // Access Strada variable 'x' (it's a StradaValue*)
        double val = strada_to_num(x);

        // Do the computation in C
        double result = sqrt(val);

        // Return a new StradaValue
        return strada_new_num(result);
    }
}
Variable Naming: Inside __C__ blocks, Strada variables are available by their name without the sigil. So $x becomes just x, and it's a StradaValue*.
Tagged Integers: Integer values may be passed as tagged pointers (with the low bit set) rather than heap-allocated StradaValue* structs. Always use strada_to_int() to extract integer values — it handles both tagged and heap-allocated integers transparently. Never dereference a StradaValue* directly to read its integer field; use the accessor functions.

Opaque Handle Pattern

C pointers can be stored in Strada int variables (which are 64-bit). This "opaque handle" pattern is the standard way to manage C resources:

__C__ {
    #include <openssl/ssl.h>

    static SSL_CTX *g_ctx = NULL;

    static void ensure_ssl_init() {
        if (!g_ctx) {
            SSL_library_init();
            g_ctx = SSL_CTX_new(TLS_client_method());
        }
    }
}

func ssl_connect(str $host, int $port) int {
    __C__ {
        ensure_ssl_init();

        char *h = strada_to_str(host);
        int p = (int)strada_to_int(port);

        // Create connection...
        SSL *ssl = SSL_new(g_ctx);
        // ... connect to host:port ...

        free(h);

        // Store pointer as int64_t
        return strada_new_int((int64_t)(intptr_t)ssl);
    }
}

func ssl_write(int $handle, str $data) int {
    __C__ {
        // Retrieve pointer from int
        SSL *ssl = (SSL*)(intptr_t)strada_to_int(handle);

        char *d = strada_to_str(data);
        int written = SSL_write(ssl, d, strlen(d));
        free(d);

        return strada_new_int(written);
    }
}

func ssl_close(int $handle) void {
    __C__ {
        SSL *ssl = (SSL*)(intptr_t)strada_to_int(handle);
        SSL_shutdown(ssl);
        SSL_free(ssl);
        return strada_undef_static();
    }
}

Usage

my int $conn = ssl_connect("example.com", 443);
ssl_write($conn, "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n");
# ... read response ...
ssl_close($conn);
Why int? Strada's int is 64-bit, large enough to hold any pointer on modern systems. The cast pattern (int64_t)(intptr_t)ptr is portable and safe.

Working with Strings

String handling requires careful memory management:

func uppercase(str $s) str {
    __C__ {
        // Extract string (allocates memory!)
        char *str = strada_to_str(s);

        // Modify in place
        for (char *p = str; *p; p++) {
            if (*p >= 'a' && *p <= 'z') {
                *p = *p - 32;
            }
        }

        // Create new StradaValue (copies the string)
        StradaValue *result = strada_new_str(str);

        // Free the temporary string
        free(str);

        return result;
    }
}

Binary Data

For binary data that may contain null bytes, use strada_new_str_len() to create the value and strada_str_len(sv) (not strlen()) to get a string's byte length:

func read_binary(int $fd, int $len) str {
    __C__ {
        // $fd and $len are the StradaValue* variables fd and len
        int cfd = (int)strada_to_int(fd);
        size_t clen = (size_t)strada_to_int(len);

        char *buf = malloc(clen);
        ssize_t n = read(cfd, buf, clen);

        if (n <= 0) {
            free(buf);
            return strada_undef_static();
        }

        // Preserve binary data including null bytes
        StradaValue *result = strada_new_str_len(buf, n);
        free(buf);
        return result;
    }
}

Shared Libraries

Creating a Shared Library

Compile your Strada code as a shared library:

# Create mylib.so from mylib.strada
./strada --shared mylib.strada

Your library can export functions that other Strada programs can call:

# lib/MathLib.strada
package MathLib;
version "1.0.0";

func add(int $a, int $b) int {
    return $a + $b;
}

func multiply(int $a, int $b) int {
    return $a * $b;
}
# Compile to shared library
./strada --shared lib/MathLib.strada
mv MathLib.so lib/

Using Library Imports

Import libraries with namespace access using any of the import methods:

use lib "lib";
import_lib "MathLib.so";       # Runtime loading (dlopen)
# Or: import_object "MathLib.o"   Static linking
# Or: import_archive "MathLib.a"  Static linking with bundled runtime

func main() int {
    my int $sum = MathLib::add(10, 32);
    my int $product = MathLib::multiply(6, 7);

    say("Sum: " . $sum);        # 42
    say("Product: " . $product); # 42

    return 0;
}
Library imports: Only the compiled file (.so, .o, or .a) is required. Function signatures are embedded via __strada_export_info(). See the Libraries Guide for details on each format.

Manual FFI

For more control, use the core::dl_* functions directly:

my int $lib = core::dl_open("./mylib.so");
my int $fn = core::dl_sym($lib, "MathLib_add");
my scalar $result = core::dl_call_sv($fn, [10, 32]);
say($result);  # 42
core::dl_close($lib);

C Callbacks (c::callback)

The reverse direction: hand a Strada closure to C code expecting a function pointer — qsort comparators, libcurl write callbacks, GTK signal handlers. c::callback($fn, "ret", "args") mints a fresh C function pointer (a libffi trampoline) that unmarshals its C arguments, invokes your closure, and marshals the return value back.

# Sort a C int64 array with a Strada comparator
my scalar $buf = c::alloc(8 * 4);
c::write_int64($buf,      42);
c::write_int64($buf + 8,   7);
c::write_int64($buf + 16, 99);
c::write_int64($buf + 24, -5);

my scalar $cmp = c::callback(fn (scalar $pa, scalar $pb) int {
    return c::read_int64($pa) <=> c::read_int64($pb);
}, "int", "ptr,ptr");

__C__ {
    typedef int (*qsort_cmp_t)(const void *, const void *);
    qsort((void *)(intptr_t)strada_to_int(buf), 4, 8,
          (qsort_cmp_t)(intptr_t)strada_to_int(cmp));
}

c::callback_free($cmp);  # optional — an exit-time sweep frees survivors
c::free($buf);

Signature strings: return type void/int/int32/num/ptr; arguments are a comma list of int/int32/num/ptr/str (max 8). str arguments arrive as Strada strings (NULL → undef); ptr values travel as int addresses — pair them with c::read_*/c::write_*. Closure captures and our globals work inside the callback. No link dependency: libffi.so is loaded lazily at the first c::callback call (ffi.h is needed at build time only; ./configure auto-detects it, --without-libffi opts out).

Calling Strada from C: Extern Functions

An extern func with a body is exported under its own name with a plain C signature, so a C program (or any language with a C FFI) calls it directly. The body is ordinary Strada: strings, hashes, our variables, other functions, try/throw. The compiler adds a small C wrapper that converts the arguments and the result.

Defining Extern Functions

# textlib.strada - functions callable from C
package TextLib;

our int $calls = 0;

# C: char *shout(char *s)
extern func shout(str $s) str {
    $calls++;
    my %seen = ();
    foreach my $w (split(/\s+/, $s)) { $seen{lc($w)}++; }
    return uc($s) . " (" . scalar(keys(%seen)) . " distinct words)";
}

# C: int64_t add(int64_t a, int64_t b)
extern func add(int $a, int $b) int { return $a + $b; }

# C: double half(double x)
extern func half(num $x) num { return $x / 2; }

# C: int64_t calls(void)
extern func calls() int { return $calls; }

Building and Calling from C

Build the library with --shared. A --shared library does not contain the Strada runtime, so the C program links it: strada --embed-ldflags prints the flags (the runtime, the libraries it uses, and -rdynamic so the library finds the runtime in the program).

/* host.c */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <dlfcn.h>

int main(void) {
    void *lib = dlopen("./textlib.so", RTLD_NOW);
    if (!lib) { fprintf(stderr, "%s\n", dlerror()); return 1; }

    char *(*shout)(const char *) = (char *(*)(const char *))dlsym(lib, "shout");
    int64_t (*add)(int64_t, int64_t) = (int64_t (*)(int64_t, int64_t))dlsym(lib, "add");
    double (*half)(double) = (double (*)(double))dlsym(lib, "half");
    int64_t (*calls)(void) = (int64_t (*)(void))dlsym(lib, "calls");

    char *s = shout("hello Hello world");
    printf("%s\n", s);                       // HELLO HELLO WORLD (2 distinct words)
    free(s);                                  // a returned string is yours to free
    printf("%ld %g %ld\n", (long)add(40, 2), half(5.0), (long)calls());  // 42 2.5 1
    return 0;
}
strada --shared textlib.strada
cc -o host host.c $(strada --embed-ldflags)
./host

Calling Them from Strada

Strada code calls an extern function like any other, with no conversion: shout("x") inside its package, and TextLib::shout("x") from a program that pulls the file in with use or loads the compiled library:

use lib ".";
import_lib "textlib.so";

func main() int {
    say(TextLib::shout("one two one"));   # ONE TWO ONE (2 distinct words)
    say(TextLib::add(40, 2));            # 42
    return 0;
}

So one library serves both C programs and Strada programs. In a package, extern func NAME is also the ordinary function Package::NAME, so a package cannot define both an extern func and a func with the same name. (In package main the extern is only the C function.)

Exceptions: an exception that escapes an extern function called from C ends the program with the usual uncaught-exception report. If the C caller must continue, catch it inside the function and return an error value.

Writing the C Wrapper by Hand

An extern func covers the types in the table above. When the C side needs a signature it cannot express — a struct pointer, a callback with a void * context, an int32 result — write the wrapper yourself in a top-level __C__ block. Any function there that is not static is an exported C symbol.

From C, a Strada function is called by its C name: the package and function name joined with underscores (Geo::Point::describe is Geo_Point_describe; in package main it is just the function name). Every parameter and the result are StradaValue*, and the result is a new reference the caller releases. Declare it before use:

# pointlib.strada
package Geo::Point;

__C__ {
typedef struct { double x, y; } point_t;

StradaValue *Geo_Point_describe(StradaValue *x, StradaValue *y);   /* the Strada function below */

/* Exported: not static. */
char *point_describe(const point_t *p) {
    StradaValue *x = strada_new_num(p->x);
    StradaValue *y = strada_new_num(p->y);
    StradaValue *r = Geo_Point_describe(x, y);
    char *out = strada_to_str(r);     /* malloc'd copy: the caller frees it */
    strada_decref(r);
    strada_decref(x);
    strada_decref(y);
    return out;
}
}

func describe(num $x, num $y) str {
    return "(" . $x . ", " . $y . ") is " . math::sqrt($x * $x + $y * $y) . " from the origin";
}

Build and call it exactly like the extern func library above (strada --shared pointlib.strada, then dlsym(lib, "point_describe") or link against it). Passing {3, 4} prints (3, 4) is 5 from the origin.

What you take on compared with extern func:

  • Conversion and reference counting are yours. Release every value you create and every result you receive; free every strada_to_str copy.
  • Libraries and executables declare differently. In a --shared, --object or --static-lib build, Strada functions are global and the declaration above is right. In a plain executable they are static inline, so the declaration must be static inline StradaValue *describe(StradaValue *x, StradaValue *y); — and an optimized executable may drop a C function nothing in the program calls.
  • One namespace. Your function's name must not match anything in the C library, the runtime, or another Strada function's C name.
  • Strada callers are unaffected. The C function is not part of the module's Strada interface; Strada code keeps calling Geo::Point::describe().
  • Compiled only for the C-to-Strada call. Under strada-interp a Strada function is not a C symbol, so a block that calls one by name fails to load. C functions that only do C work run in the interpreter as usual.

Complete Example: Compression Library

Here's a complete example wrapping zlib for compression:

package Compress;

__C__ {
    #include <zlib.h>
    #include <stdlib.h>
    #include <string.h>
}

func gzip(str $data) str {
    __C__ {
        char *input = strada_to_str(data);
        size_t input_len = strada_str_len(data);  // binary-safe length

        // Allocate output buffer (worst case: slightly larger than input)
        uLongf output_len = compressBound(input_len);
        char *output = malloc(output_len);

        // Compress
        int ret = compress((Bytef*)output, &output_len,
                          (Bytef*)input, input_len);

        free(input);

        if (ret != Z_OK) {
            free(output);
            return strada_undef_static();
        }

        StradaValue *result = strada_new_str_len(output, output_len);
        free(output);
        return result;
    }
}

func gunzip(str $data, int $max_size) str {
    __C__ {
        char *input = strada_to_str(data);
        size_t input_len = strada_str_len(data);  // binary-safe length
        uLongf output_len = (uLongf)strada_to_int(max_size);

        char *output = malloc(output_len);

        int ret = uncompress((Bytef*)output, &output_len,
                             (Bytef*)input, input_len);

        free(input);

        if (ret != Z_OK) {
            free(output);
            return strada_undef_static();
        }

        StradaValue *result = strada_new_str_len(output, output_len);
        free(output);
        return result;
    }
}

Compile with the zlib library:

./strada --shared compress.strada -lz

C Interop in the Interpreter

Programs that use C interop also run under the bytecode VM (strada-interp):

  • __C__ blocks are JIT-compiled: the VM compiles a program's __C__ blocks with the C compiler into one shared object (so file-scope static state is shared between blocks), caches it in ~/.cache/strada/cblocks/, and loads it with dlopen. Libraries a module declares with link_lib are linked into that object. A C compiler is therefore needed at run time for such programs.
  • c::callback, the c:: memory helpers, import_lib libraries and the core::dl_* functions work as in compiled programs.
  • Body-less extern func declarations (extern func my_c_function(int $x) int;) call the C function in the VM too: the arguments and result are converted with the same C types as in compiled code.
  • Compiled-only: a __C__ block that calls a Strada function by its C name (see Writing the C Wrapper by Hand) fails to load in the VM. Also compiled-only: functions declared in an extern "C" { ... } block are not callable in the VM — calling one throws extern "C" function NAME() is not available in the bytecode VM (compiled backend only). Raw pointers into Strada variables (core::int_ptr(\$x), core::num_ptr) are also compiled-only; the VM raises an error.

Best Practices

Always Free Strings

strada_to_str() allocates memory. Always free() the result when done.

Check for NULL

Strada values can be undef. Check before extracting to avoid crashes.

Use Static Helpers

Put complex C logic in static helper functions in top-level blocks for cleaner code.

Document Handle Types

When using the opaque handle pattern, document what type of pointer each int handle represents.

Debugging Tips

  • Compile with -g flag for debug symbols: ./strada -g program.strada
  • Use -c to keep the generated C file for inspection: ./strada -c program.strada
  • Add printf() statements in your __C__ blocks for debugging
  • Use GDB to debug the compiled executable
# Compile with debug info
./strada -g -c myprogram.strada

# Debug with GDB
gdb ./myprogram
